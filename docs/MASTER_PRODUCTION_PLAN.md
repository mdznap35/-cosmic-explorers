# 0. الهدف النهائي ومعيار النجاح

نبني لعبة يشعر الطفل أنه يعيش داخل عالم فضائي له شخصيات ومركبة وغرف ومناطق ومغامرات. يدخل السفينة، يختار من يقود الرحلة، يجهز الأدوات، يسافر إلى وجهة، يستكشف ويلعب ويكتشف شيئاً، يعود ليعرض ما وجده، ثم يفتح فرصاً جديدة.

**المنتج النهائي ليس:** واجهة ثابتة للكواكب، ولا موسوعة نصية مع أسئلة متكررة، ولا مجموعة صور وحوارات، ولا لعبة تعتمد على القراءة وحدها، ولا تجميعة أصول جاهزة متنافرة.

**المنتج النهائي هو:** لعبة ثلاثية الأبعاد فعلية بشخصيات متحركة وتفاعل حقيقي، حملة قصصية طويلة، أنشطة علمية وترفيهية متنوعة، سفينة ومختبر وورشة ومعرض وأركيد، محتوى علمي موثق، وتقدم محلي يعمل دون اتصال.

## معيار النجاح الأعلى

يستطيع الطفل إكمال حلقة لعب ممتعة من البداية للنهاية دون مساعدة مستمرة: يلاحظ هدفاً، يتحرك أو يختار أداة، يجرب، يرى نتيجة مفهومة، يتلقى استجابة ودودة، يحفظ اكتشافاً أو يحصل على مكافأة، ويعرف كيف يواصل أو يعود. وفي الوقت نفسه يستطيع تجاهل الشرح العلمي واللعب بالأركيد أو التزيين عندما يريد.

# 1. ثوابت المنتج والقيود

## الجمهور والتجربة
- التصميم موجّه لطفل في بدايات القراءة، مع قابلية توسيع طبقات المحتوى.
- العربية هي اللغة الأساسية، مع دعم RTL وتكبير النصوص حيث يلزم.
- الصوت اختياري، وكل نشاط قابل للفهم دون صوت.
- أدوات التحكم كبيرة ولمسية، مع إيماءات بسيطة وتعليمات مصورة.
- دعم جلسات قصيرة والاستئناف، دون عقوبة عند ترك اللعبة.

## السلامة والخصوصية
- لا إعلانات، ولا مشتريات داخل اللعبة، ولا صناديق حظ.
- لا دردشة عامة أو مشاركة اجتماعية أو قوائم متصدرين عامة.
- لا حساب طفل ولا تحليلات ولا جمع بيانات شخصية.
- الحفظ محلي، واللعبة الأساسية لا تعتمد على اتصال شبكي.
- لا عدّادات يومية أو سلاسل دخول أو رسائل لوم عند الغياب.

## الدقة العلمية
- حقيقة ودليل وفرضية وخيال لها تصنيفات منفصلة.
- لا ندّعي اكتشاف حياة خارج الأرض.
- لا هبوط على الشمس أو داخل المشتري وزحل كما لو كانا سطحاً صلباً.
- الرحلات الخيالية والأجهزة غير الواقعية توسم بأنها عناصر قصصية.
- كل خريطة أو نموذج أو مؤثر علمي يسجل مصدره وترخيصه وتاريخ مراجعته.
- أي مشهد مضغوط المقاييس يوضح أن الأحجام والمسافات تقريبية.

## القيود التقنية
- المحافظة على Godot 4.7.2 وCompatibility/OpenGL ES حتى يثبت اختبار الجهاز سبباً لتغييرهما.
- الاستهداف الأول Android ARM64.
- مراعاة جهاز متوسط أو محدود الإمكانات؛ الأداء يُقاس على هاتف فعلي ولا يُفترض.
- لا تنزيلات كبيرة على هاتف المستخدم دون تقدير الحجم وموافقته؛ CI هو مكان جلب الأصول وبناء APK متى أمكن.
- لا دمج أو نشر إلى main دون موافقة منفصلة.
- الحفاظ على تاريخ المشروع؛ العزل بفروع وPRs صغيرة قابلة للمراجعة.

# 2. تصميم تجربة اللعب الأساسية

## حلقة الرحلة الكبرى
1. اختر: يتلقى الفريق اقتراح رحلة أو يختار الطفل منطقة مفتوحة.
2. جهّز: يختار أدوات المسح أو مركبة آلية أو تخصيصاً شكلياً.
3. انطلق: مشهد قصير قابل للتخطي، ثم انتقال إلى منطقة الرحلة.
4. استكشف: حركة حرة، كاميرا، نقاط اهتمام، وأسرار اختيارية.
5. تفاعل: أداة أو لغز أو لعبة حركة أو نشاط علمي.
6. اكتشف: توثيق ملاحظة أو صورة أو عينة افتراضية أو بطاقة معرفة.
7. ارجع: عودة اختيارية إلى سَنا مع ملخص مصور.
8. اعرض وافتح: أضف للمعرض، استلم مكافأة، وافتح مهمة أو نشاطاً جديداً.

## حلقة النشاط القصير
مشاهدة أو سماع التلميح ← فهم الفعل المطلوب ← لمس أو سحب أو تركيب أو تصوير ← نتيجة بصرية ← محاولة أخرى أو خروج ← مكافأة أولى اختيارية.

## توزيع الإيقاع
- مغامرات القصة تعطي الاتجاه والمعنى العاطفي.
- الاستكشاف الحر يمنح الطفل حرية الاختيار.
- التعليم التفاعلي يحول فكرة واحدة إلى تجربة.
- الألعاب المستقلة تقدم ترفيهاً خالصاً لا يحتاج معلومة.
- التخصيص والجمع يربطان العودة بعالم اللاعب.
لا نضع درساً بعد كل لعبة، ولا نجعل القصة تتوقف لمحاضرة طويلة.

# 3. العمارة المستهدفة

## طبقات التطبيق
1. App Shell: بدء التطبيق، الإعدادات، اللغة، المشاهد والرجوع.
2. World Layer: السفينة، المدار، سطح العالم، المختبر، الأركيد.
3. Character Layer: حركة الشخصيات، تبديلها، التفاعل والتعابير.
4. Interaction Layer: عقود موحدة للأبواب والأدوات والعينات والنقاط.
5. Content Layer: فصول ومهمات وحوارات وبطاقات علمية وألعاب ومكافآت كبيانات.
6. Progression Layer: فتح المناطق والأهداف والمجموعات والأوسمة.
7. Persistence Layer: حفظ محلي بإصدار وترحيل واختبار.
8. Presentation Layer: واجهة عربية وصوت وكاميرا ومؤثرات وإتاحة.
9. Quality Layer: اختبارات بيانات وأنظمة وسموك وفحص APK وأداء الهاتف.

## الأنظمة المشتركة المطلوبة
- ContentRegistry: قراءة المحتوى والتحقق من سلامته.
- MissionDirector: تتبع الهدف الرئيسي والاختياري والأحداث.
- DialogueDirector: عقد الحوار والاختيارات والتخطي والترجمة.
- CharacterRoster: اختيار الشخصية وربط قدراتها وسياقها.
- InteractionRouter: توحيد التفاعل مع عناصر العالم.
- SaveService: حفظ وتحميل وترحيل آمن.
- DiscoveryJournal: سجل الصور والبطاقات والعينات.
- RewardService: منح المكافآت مرة واحدة مع منع التكرار.
- WorldMap وTravelDirector: خريطة الوجهات وانتقالات المناطق.
- ActivityLauncher: تشغيل الألعاب القصيرة والعودة منها دون فقد الحالة.
- AudioDirector: أصوات وموسيقى ومستويات وكتم اختياري.
- AccessibilitySettings: حجم النص ومستوى المساعدة والحركة والصوت.

## الهيكل المقترح
- data/content: بيانات JSON ذات schema version.
- scripts/content: قراءة وتحقيق بيانات المحتوى.
- scripts/gameplay: المهمات والتفاعلات والتقدم.
- scripts/characters: الشخصيات والتحريك والتبديل.
- scripts/world: المناطق والسفر والبوابات.
- scripts/services: الحفظ والصوت والمكافآت.
- scenes/characters: مشاهد الشخصيات.
- scenes/ship: سفينة سَنا وغرفها.
- scenes/worlds: مشاهد المناطق.
- scenes/activities: الألعاب المصغرة.
- scenes/ui: واجهات قابلة لإعادة الاستخدام.
- assets: أصول منظمة مع سجل ترخيص ومصدر.
- tests: اختبارات بيانات وتكامل وسموك.
- docs: تصميم وقرارات ومراجعات وحالة تنفيذ.

يتوسع الهيكل تدريجياً؛ لا ننشئ مجلدات فارغة كثيرة دون استخدام.

# 4. خارطة التنفيذ بمراحل وبوابات قبول

## P0 — تثبيت الحوكمة والرؤية
**المخرجات:** خطة الإنتاج، سجل الحالة، قاموس المصطلحات، مصفوفة المخاطر، وقرارات التقنية.

المهام:
- P0.1 تثبيت تعريف المنتج والنطاق وغير الأهداف.
- P0.2 وضع معايير جودة للعب والعلم والخصوصية والأداء.
- P0.3 تحديد المصدر الوحيد لحالة المشروع والمرحلة التالية.
- P0.4 فصل فروع المحتوى والتنفيذ عن main وعن PRs القائمة.

**القبول:** كل قرار له سبب ومسار؛ ولا تتعارض الوثائق مع الكود أو حالة الفروع.

## P1 — خط محتوى قابل للفحص (بدأ التنفيذ)
**المخرجات:** JSON موحد، قارئ بيانات، تحقق IDs ومراجع، بيانات القصة الأولية، واختبار آلي على CI.

المهام:
- P1.1 تعريف schema version.
- P1.2 تعريف بيانات الفصول والمهمات والحوارات والبطاقات العلمية والمكافآت.
- P1.3 بناء ContentRegistry مع أخطاء مفهومة.
- P1.4 فحص الروابط بين السجلات والـIDs والمصادر وعقد الحوار.
- P1.5 عينات فعلية للفصل التمهيدي والقمر والمريخ.
- P1.6 إدخال الاختبار في GitHub Actions.
- P1.7 تثبيت عقد الترحيل والتوافق مع الحفظ الحالي.

**القبول:** يقرأ Godot ملفات JSON ويجتاز كل التحققات؛ وتفشل الاختبارات عمداً عند ID مكرر أو مرجع مفقود أو مسار حوار مكسور.

## P2 — إثبات الشريحة البصرية والحركية
**المخرجات:** هدف فني بصري مرجعي، ثلاثة نماذج شخصيات أصلية قابلة للتحريك، وكاميرا وتحكم لمسي.

المهام:
- P2.1 Character sheets نهائية لريم وسليم ولولو.
- P2.2 نموذج 3D أولي متناسق لكل شخصية.
- P2.3 Rig بشري موحد لريم وسليم مع تعابير وملحقات.
- P2.4 Rig مخصص للحلزون: جسم وقرون وعينان وصدفة وانكماش وتمدد.
- P2.5 حالات حركة: idle وwalk وrun وfloat وinspect وinteract وreact وcelebrate.
- P2.6 CharacterRoster والتبديل مع حفظ الشخصية المختارة.
- P2.7 ضبط الكاميرا ومسافة المتابعة ومناطق اللمس.
- P2.8 فحص الشكل والحركة على هاتف فعلي.

**القبول:** تبديل الشخصيات لا يعيد تحميل المشهد، وكل شخصية تتحرك وتتفاعل بشكل مقنع؛ لولو لا يستخدم Rig بشرياً معاد التلوين.

## P3 — سفينة سَنا كمركز لعب
**المخرجات:** سفينة ثلاثية الأبعاد قابلة للتجول، والغرف الأساسية متفاعلة.

الغرف: جسر القيادة، الورشة، المختبر، ركن لولو، قبة النجوم، المعرض، الأركيد، صالة الفريق.

المهام:
- P3.1 بناء ممر مركزي وغرفة قيادة بمستوى جودة مرجعي.
- P3.2 أبواب ونقاط تفاعل وعلامات بصرية.
- P3.3 لوحات اختيار الرحلة والمركبة والأدوات.
- P3.4 حفظ التخصيصات، دون جعل تصميم الغرفة حاجز تقدم.
- P3.5 تقديم الشخصيات بحوارات قصيرة قابلة للتخطي.

**القبول:** اللاعب يستطيع التجول ودخول الغرف والتفاعل والرجوع، ثم استئناف حالة السفينة بعد إعادة التشغيل.

## P4 — السفر والصاروخ والمركبة
**المخرجات:** تجربة إطلاق وسفر مداري وهبوط آلي قابلة للعب، لا مجرد فيديو.

المهام:
- P4.1 واجهة الوجهات وخريطة النظام الشمسي.
- P4.2 تجهيز الرحلة واختيار الحمولة وأدوات المسح.
- P4.3 تسلسل إطلاق تفاعلي مبسط.
- P4.4 انتقال مداري مع نقاط تفاعل ومناورة لطيفة.
- P4.5 فصل واضح بين زيارة المدار والهبوط على سطح مناسب.
- P4.6 مركبات آلية للمواقع التي لا يناسبها هبوط الطاقم.
- P4.7 العودة والملخص والحفظ.

**القبول:** رحلة واحدة على الأقل تبدأ من السفينة وتنتهي بالعودة ويمكن إعادة تشغيلها، مع احترام حقائق الوجهة وعدم ادعاء محاكاة فلكية دقيقة.

## P5 — أول عالم مكتمل: المريخ
**المخرجات:** منطقة لها ممرات ونقاط اهتمام وتضاريس وأسرار وروفر ومختبر.

المهام:
- P5.1 مشهد وصول ومدار المريخ.
- P5.2 منطقة سطح مصممة ومقسمة إلى وحدات تحميل.
- P5.3 تحكم روفر وتوجيه لمسي.
- P5.4 مسح صخور وتصوير آثار سطحية.
- P5.5 نشاط فصل الملاحظة عن الاستنتاج حول الماء القديم.
- P5.6 نقل عينة افتراضية وتحليلها في المختبر.
- P5.7 سجل اكتشافات ومكافأة وعودة.
- P5.8 أسرار اختيارية ومهمة إعادة لعب.

**القبول:** مغامرة end-to-end قابلة للعب، لها بداية ووسط ونهاية ومكافأة محفوظة مرة واحدة، وليست مجرد مشاهد منفصلة.

## P6 — نظام المهمات والحوار
**المخرجات:** MissionDirector وDialogueDirector ونظام event-driven مع إمكانية إضافة المحتوى دون ربطه بسكربت واحد.

المهام:
- P6.1 أهداف مطلوبة واختيارية وتقدم مرئي.
- P6.2 تلميحات متدرجة وقابلة للإخفاء.
- P6.3 حوار بشروط واختيارات آمنة.
- P6.4 تخطي الحوار وإعادته وعدم تعطيل اللعب.
- P6.5 أحداث مسموحة ومحدودة من الملفات؛ لا تنفيذ كود اعتباطي من JSON.
- P6.6 اختبارات مسارات الحوار والانتقالات والحفظ.

**القبول:** لا مهمة تتعطل بسبب اختيار غير متوقع أو إغلاق مشهد؛ كل عقدة حوار قابلة للوصول أو موسومة بقصد.

## P7 — المختبر ومكتبة التعلم
**المخرجات:** 100+ بطاقة علمية تدريجية على مراحل الإنتاج، وتجارب قصيرة متعددة.

المهام:
- P7.1 بطاقات شاهد وافهم واعرف أكثر.
- P7.2 التمييز المرئي بين حقيقة ودليل وفرضية وخيال.
- P7.3 أنشطة ظل وضوء ومدار وتصنيف وتصوير وروفر.
- P7.4 صور علمية وتصورات فنية موسومة بشكل صحيح.
- P7.5 روابط المصادر في metadata لا كروابط تصفح داخل تجربة الطفل.
- P7.6 مراجعة علمية للنصوص والأرقام القابلة للتغير.

**القبول:** كل بطاقة لها مصدر وتاريخ تحقق ودرجة يقين؛ لا يمكن للنصوص ادعاء نتيجة غير مثبتة.

## P8 — الأركيد واللعب الخالص
**المخرجات:** مجموعة ألعاب صغيرة مستقلة ذات تنوع ميكانيكي، يمكن فتحها من السفينة.

الفئات: حركة خفيفة، متاهات، تصوير وفن، تركيب وبناء، ذاكرة وملاحظة، إيقاع، تزيين.

المهام:
- P8.1 لعبة واحدة من كل فئة كإثبات.
- P8.2 واجهة إطلاق موحدة والعودة إلى السفينة.
- P8.3 إعدادات مساعدة وصعوبة مرنة.
- P8.4 إعادة اللعب والتنوع دون ضغط أو عقوبة.
- P8.5 بناء بقية الألعاب بعد اختبار عودة الطفل إليها فعلاً.

**القبول:** لا تعتمد كل الألعاب على اختيار من متعدد؛ لكل لعبة تعليمات مفهومة وطريقة خروج وإعادة تشغيل.

## P9 — الجوائز والمجموعات والتخصيص
**المخرجات:** DiscoveryJournal وRewardService وألبومات وأوسمة وملصقات وديكور وطلاء.

المهام:
- P9.1 منح المكافأة عند حدث واحد مع منع التكرار.
- P9.2 سجل اكتشافات وصور وبطاقات.
- P9.3 ألبومات الشمس والكواكب والأقمار والأجرام والظواهر والأدوات والشخصيات والفن.
- P9.4 ديكور السفينة وطلاء المركبة وأزياء تجميلية.
- P9.5 لوحة تقدم لا تقارن الطفل بغيره.
- P9.6 ترحيل الحفظ دون فقدان الإنجازات.

**القبول:** كل مكافأة تُحفظ وتظهر بعد إعادة التشغيل، ولا تحتاج لاتصال أو دخول يومي.

## P10 — توسيع النظام الشمسي والفضاء العميق
**المخرجات:** عوالم إضافية مبنية على الوحدات والبيانات التي أثبتها المريخ.

ترتيب التوسع:
1. الأرض والقمر.
2. عطارد والزهرة.
3. حزام الكويكبات وسيريس.
4. المشتري وأقمار آيو وأوروبا وغانيميد وكاليستو.
5. زحل وتيتان وإنسيلادوس.
6. أورانوس ونبتون وأقمارهما.
7. بلوتو وحزام كايبر والمذنبات.
8. النجوم والسدم والمجرات والكواكب الخارجية.

**القبول:** لكل منطقة هوية بصرية وتفاعلات ومعلومة وأسرار ومهمة؛ لا نكرر سطحاً واحداً مع تغيير اللون فقط.

## P11 — الصوت والواجهة والإتقان
**المخرجات:** موسيقى أصلية، أصوات تفاعل، حوارات مسموعة اختيارياً، حركات وتعبيرات، انتقالات، وإتاحة.

**القبول:** كتم الصوت لا يعطل اللعب؛ لا تتداخل الموسيقى مع الكلام؛ كل المشاهد قابلة للتخطي؛ لا توجد نصوص مقصوصة أو أزرار صغيرة على الهاتف.

## P12 — الاختبارات والإطلاق
**المخرجات:** APK قابل للتثبيت، اختبارات CI، قبول فعلي على الجهاز، وسجل إصدار واضح.

الاختبارات:
- Parsing واستيراد كل مورد.
- Unit tests للبيانات والمدارات والمكافآت والترحيل.
- Integration tests للحوار والمهمات والتفاعل والحفظ.
- Smoke test للمشاهد الأساسية.
- تصدير Android وفحص package وABI وpermissions.
- فحص عدم وجود INTERNET permission في نسخة offline.
- قياس FPS والذاكرة والحرارة وحجم APK على Galaxy A15.
- اختبار جلسة لعب فعلية وملاحظة مواضع الالتباس.
- مراجعة الترخيص والنسب لكل أصل.

**القبول النهائي:** لا أخطاء مانعة؛ لا فقدان تقدم؛ يعمل اللعب الأساسي دون شبكة؛ نتائج الأداء مقاسة على الجهاز؛ وكل ما لم يُختبر يُذكر صراحة.

# 7. جودة اللعب والمحتوى

## أول دقيقة
- مشهد افتتاح قصير وتفاعل خلال أول دقيقة.
- توجيه بصري دون فقرة قراءة.
- لا تسجيل حساب أو نافذة إذن شبكة.

## كل مهمة
- فعل أساسي واحد واضح.
- تلميح بصري أولاً، ثم تلميح لغوي اختياري.
- لا خسارة تقدم بسبب الخطأ.
- مكافأة أو ملاحظة ذات معنى.
- زر خروج وعودة واضح.

## كل منطقة
- صورة ظلية يمكن تمييزها عن المناطق الأخرى.
- حركة أو تفاعل بيئي واحد على الأقل.
- نقطة اهتمام رئيسية وأسرار اختيارية.
- نشاط علمي ونشاط مرح أو فني.
- تسجيل اكتشاف واحد أو أكثر.

## الشخصيات
- حركات idle وreact وcelebrate مختلفة.
- حوار متنوع قصير.
- لكل شخصية دور متكرر لكنه ليس حصرياً.
- لا تُختزل شخصية لولو إلى نكتة أو مفتاح باب.

# 8. ميزانية الأداء والاختبار

- هدف أولي: 30 إطاراً/ثانية مستقرة في مشاهد اللعب القياسية على الجهاز المرجعي؛ 60 إطاراً إذا أثبت القياس إمكانية ذلك دون ارتفاع حرارة أو تقطيع.
- استخدام LOD أو meshes منخفضة عند البعد.
- تخفيض خامات المشاهد غير القريبة وضغطها قبل الشحن.
- تجنب الظلال الديناميكية الثقيلة والطبقات الشفافة المتراكبة.
- تحميل المناطق عند الحاجة وتحرير موارد المنطقة السابقة.
- عدم إنشاء Nodes أو Materials كثيرة ديناميكياً في كل إطار.
- قياس بدء التطبيق والتحميل والتنقل وعودة الخلفية.
- لا نضع رقماً نهائياً لحجم APK أو الذاكرة قبل بناء الشريحة وقياسها؛ نراقب الزيادة في كل PR.

# 10. إدارة التنفيذ

- كل مرحلة لها PR أو دفعة واضحة.
- كل PR يذكر الهدف والملفات والتغيير السلوكي والاختبارات والقيود.
- لا merge تلقائي ولا تعديل main مباشرة.
- عبارة «بُني» ليست دليلاً؛ نطلب CI وسجلات واختبار جهاز عند الحاجة.
- الحالة المرجعية في docs/IMPLEMENTATION_STATUS.md.
- إذا تعذر جزء، ننجز أعلى جزء مستقل لا يعرّض المشروع للخطر.
- نوقف إضافة أفكار جديدة إلى أن يكتمل العمود الفقري؛ ونضعها في backlog.
- الخطة حيّة: تُحدّث بعد كل بوابة بناء على الاختبارات واللعب.

# 11. تعريف اكتمال المنتج

لا يُعلن إطلاق اللعبة إلا إذا:
- اكتملت حلقة رحلة رئيسية واحدة على الأقل بشكل متقن وقابل للإعادة.
- توجد شخصيات ثلاثية الأبعاد فعلية ذات تحريك وتفاعلات.
- تعمل السفينة والرحلات والمناطق دون انقطاع غير مفهوم.
- توجد أنشطة تعليمية وأنشطة ترفيهية فعلية متنوعة.
- تعمل المهمات والحوارات والمكافآت والحفظ.
- المحتوى العلمي موثق ومراجع.
- اللعبة تعمل offline.
- لا توجد مشتريات أو إعلانات أو دردشة أو جمع بيانات طفل.
- اجتازت CI واختبارات الجهاز والقبول.
- توجد قائمة صريحة بأي عيوب متبقية.

**الأولوية الحالية:** إكمال P1 (ContentRegistry + JSON + validator + CI)، ثم بناء vertical slice للمريخ بدءاً من السفينة وانتهاء بالعودة والمعرض.
