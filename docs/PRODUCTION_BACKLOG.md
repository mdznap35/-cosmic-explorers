# خطة الإنتاج — تحويل الموسوعة إلى لعبة قابلة للعب

## قاعدة الإدارة

كل مرحلة تنتج شيئاً قابلاً للمشاهدة والاختبار. لا نعتبر كتابة الخطة تنفيذاً. لا ندمج PR أو نغيّر main دون موافقة صريحة. نعمل على فرع معزول ونحافظ على مرجع لكل قرار.

## المرحلة A — تثبيت المحتوى (هذه الحزمة)

- [x] إنشاء فرع مستقل للمحتوى.
- [x] كتابة هوية المنتج ومبادئه.
- [x] كتابة العالم والشخصيات والافتتاحية.
- [x] كتابة هيكل الحملة والفصول.
- [x] إعداد سجل المهمات والأنشطة الجانبية.
- [x] إعداد قائمة ألعاب مصغرة وترفيهية.
- [x] وضع نظام المكافآت والمجموعات.
- [x] وضع أطلس العلوم وقواعد اليقين.
- [x] دراسة مراجع ألعاب ومصادر علمية.
- [x] إعداد سجل موارد مرشحة مع حالة الاعتماد.

## المرحلة B — حسم التصميم والنموذج

- مراجعة أسماء الشخصيات مع ولي الأمر/الطفل عند عرض نموذج أولي، دون تعطيل التقدم.
- إعداد Character sheets ورسوم concept أصلية للشخصيات الثلاث.
- إنشاء vertical slice للمريخ: سَنا → التحضير → الرحلة → المدار → سطح مريخ خيالي مستند إلى الجيولوجيا → روفر → عينة → مختبر → العودة → معرض.
- صنع غرفة واحدة في السفينة قابلة للتفاعل.
- صنع لعبة مصغرة مستقلة مكتملة.
- إعداد نموذج حوار ومهمات ببيانات منفصلة عن كود المشاهد.

**قبول المرحلة:** يستطيع اللاعب إكمال حلقة لعب من البداية للنهاية، والتحكم بالشخصية، والتفاعل مع أداة، ورؤية نتيجة ومكافأة، وحفظ التقدم ثم استعادته.

## المرحلة C — الأنظمة الأساسية

1. CharacterController للطفلة والشاب، وتحريك خاص للحلزون.
2. تبديل الشخصيات والحركات والتعابير.
3. نظام تفاعل موحد للأبواب والأدوات والعينات والواجهات.
4. نظام حوار بفروع خفيفة، skip، autoplay اختياري، صوت ونص.
5. Quest/Objective manager مع شروط وأهداف اختيارية.
6. نظام حفظ محلي بإصدار وترحيل.
7. سجل اكتشافات ومجموعات ومكافآت.
8. نظام محتوى data-driven مع تحقق من الروابط والمعرفات.
9. نظام إعدادات: صوت، نص، حركة، مساعدة، صعوبة.
10. نظام وصول/رجوع واضح في كل مشهد.

## المرحلة D — العالم والمناطق

- بناء ممر/غرفة السفينة كمركز رئيسي.
- بناء منطقة القمر، ثم المريخ، كنموذج جودة مرجعي.
- استخراج وحدات بيئة قابلة لإعادة الاستخدام.
- إنشاء مستويات مدارية للمشتري وزحل وأورانوس ونبتون.
- تخصيص مشاهد فريدة للأقمار والأجرام الصغيرة.
- بناء خريطة انتقال سهلة، لا تحميل عالم كامل دفعة واحدة.

## المرحلة E — المحتوى

- كتابة النص العربي النهائي لكل مهمة.
- مراجعة علمية مستقلة لكل بطاقة.
- تسجيل/إنتاج صوت اختياري وتوليد subtitles من المصدر نفسه.
- كتابة حوارات المشاهد والأحداث الجانبية.
- إنشاء 30+ minigame في مجموعات إنتاجية، وليس نسخاً متشابهة.
- إضافة الأوسمة والملصقات والتخصيص.
- تجهيز محتوى قابل للتوسع وإصدارات بيانات.

## المرحلة F — الاختبار والجودة

- تشغيل الاختبارات الآلية للبيانات والحفظ والمهام.
- اختبار كامل للمهمات الرئيسية والرجوع والحفظ والاستئناف.
- فحص العربية RTL والخطوط والقص.
- اختبار اللمس على شاشة Galaxy A15 المستهدف.
- قياس FPS والذاكرة والحرارة واستهلاك التخزين في جلسة فعلية.
- فحص ملفات APK والصلاحيات والاعتماديات.
- تجربة لعب حقيقية مع الطفل تحت إشراف بالغ؛ مراقبة ما يفهمه دون تلقينه الإجابات.
- إصلاح أكثر نقاط التعثر تكراراً قبل التوسع.

## معايير الجودة الملزمة

### جودة اللعب
- أول تفاعل ممتع خلال أول دقيقة.
- لا يوجد طريق مسدود بسبب عدم قراءة نص.
- يستطيع الطفل الرجوع من كل مشهد.
- لا تختفي المكافآت أو التقدم بعد إغلاق التطبيق.
- لا تكون كل الأنشطة اختياراً من متعدد.

### جودة العلم
- كل حقيقة لها مصدر وتاريخ مراجعة.
- الفرضية موسومة بأنها فرضية/احتمال.
- لا تُعرض صور فنية كصور أصلية.
- النماذج المبسطة تحمل توضيحاً عند الحاجة.

### جودة الهاتف
- قياس الأداء على الجهاز الفعلي، لا بالاعتماد على CI فقط.
- استخدام مستويات تفاصيل وأحجام خامات مناسبة.
- تقليل المؤثرات الشفافة الثقيلة والظلال الديناميكية.
- تحميل المنطقة المطلوبة فقط، وإدارة الذاكرة عند الانتقال.
- لا تنزيلات كبيرة على هاتف المستخدم دون موافقة؛ التنزيل والبناء قدر الإمكان في GitHub Actions.

## ما لا نفعله الآن

- لا نعيد كتابة كامل كود اللعبة قبل إثبات vertical slice.
- لا نضيف مكتبات ضخمة دون اختبار.
- لا نخلط الكود والمحتوى في سكربت واحد طويل.
- لا نضع كل الموارد في APK دون قياس الحجم.
- لا ندّعي أن اللعبة «شهر كامل» بمجرد كتابة قائمة أنشطة؛ يجب أن يكون كل نشاط حقيقياً وممتعاً وقابلاً للاختبار.

## حالة هذا التسليم

هذه الحزمة تسلّم وثائق المحتوى والتصميم والبحث على فرع مستقل. لم تُنفّذ الشخصيات ثلاثية الأبعاد، أو الصاروخ، أو المهمات الفعلية، أو الألعاب المصغرة داخل Godot في هذا التسليم. الخطوة البرمجية الأعلى قيمة بعد مراجعة الحزمة هي تنفيذ شريحة المريخ الكاملة واختبارها على الهاتف المستهدف.
